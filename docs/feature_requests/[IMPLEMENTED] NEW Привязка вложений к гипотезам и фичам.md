# Проблема

Библиотека вложений продукта уже есть: файлы загружаются, дедуплицируются и удаляются на уровне продукта. Их ещё нельзя прикрепить к работе — к гипотезам и фичам, — поэтому материалы снова живут отдельно от сущностей, к которым относятся.

# Решение

Добавить **привязку уже существующих вложений** к гипотезам и фичам. Сам файл по-прежнему принадлежит продукту; связь — отдельный слой. Цели и прочие сущности в это требование не входят.

Опора: уже сделанная библиотека — `[IMPLEMENTED] NEW Библиотека вложений продукта.md`.

## Связи

- Один файл можно прикрепить к нескольким гипотезам и нескольким фичам; у одной гипотезы или фичи — несколько файлов.
- Открепить ≠ удалить файл: в редакторе только отцепление связи.
- Схема: отдельные junction-таблицы (гипотезы и фичи). Таблица `attachments` про типы сущностей не знает.
- Удаление гипотезы или фичи снимает только связи; файл в библиотеке остаётся.
- Клонирование гипотезы в том же продукте по умолчанию копирует **связи** с вложениями, без повторной загрузки и без дубля в Storage.

## Наследование при создании из связанной сущности

Если фича создаётся из гипотезы или гипотеза — из фичи (уже существующие сценарии «Create Feature» / «Discovery this feature»), новая сущность получает **те же прикрепления**, что были у исходной: те же вложения библиотеки, без копирования файлов.

Ручная смена линка гипотеза↔фича в редакторе вложения не переносит и не снимает.

## Управление из редактора

Привязка инициируется из редактора гипотезы и из редактора фичи.

- На основном редакторе — кнопка, открывающая **отдельный попап** управления вложениями этой сущности.
- В попапе: список уже прикреплённых, прикрепить файл из библиотеки продукта, загрузить новый (как в библиотеке: дедуп по хешу — если такой файл уже есть, использовать его и прикрепить, не создавая дубль).
- Из попапа можно **отцепить** файл от текущей сущности. Удалить файл из продукта отсюда нельзя.

Превью, теги и правку `.md` не делать.

## Удаление из раздела вложений

Полное удаление файла на странице библиотеки **автоматически снимает все связи** с гипотезами и фичами, где он был прикреплён, в том числе если сущность в архиве, закрыта или иначе не в активном списке. Ручное предварительное отцепление не требуется.

## Пометки в библиотеке

В списке вложений нужно явно видно, что файл привязан к гипотезам и/или к фичам (два независимых признака). Полное перечисление связанных сущностей пока не нужно.

## Вне scope

Цели, полиморфная связь «тип + id» в одной таблице, блокировка удаления, пока есть живые связи, экспорт бинарников в Git.

## Реализация

### Выполненные изменения:

1. **Junction-таблицы** `hypothesis_attachments` и `feature_attachments`: PK из пары id, каскад при удалении сущности или файла, триггер «тот же продукт», RLS без UPDATE.
2. **Попап** `EntityAttachmentsDialog` из редакторов сохранённой гипотезы и сохранённой фичи: список, прикрепить из библиотеки, загрузить (дубль по хешу прикрепляет существующий), отцепить. Удаления файла нет.
3. **Наследование связей** при Clone гипотезы, Create Feature from Hypothesis и Discover this feature — копируются только связи, без дубля в Storage. Ручная смена Linked Hypothesis вложения не трогает.
4. **Библиотека**: бейджи Hypotheses / Features; удаление файла снимает все связи каскадом.

Отклонений от исходного требования нет. Попап доступен только после сохранения сущности (как Clone).
