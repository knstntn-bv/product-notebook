# Проблема

В продукте нет места для файлов: исследования, скрины, PDF, черновики. Сейчас такие материалы либо теряются вне блокнота, либо неформально живут в текстовых полях. Привязка файлов к гипотезам и другим сущностям нужна, но сначала должна появиться сама сущность вложения.

# Решение

Ввести **библиотеку вложений на уровне продукта** — без связей с гипотезами, фичами и целями на первом этапе.

## Первый этап

1. **Сущность вложения** в БД и в приложении: файл принадлежит продукту, а не отдельной записи гипотезы или фичи.
2. **Дедупликация** по содержимому внутри одного продукта (например по хешу). Одинаковые байты не создают второй объект в хранилище; пользователь видит, что такой файл уже есть.
3. **Права доступа** как у остальных данных продукта: видеть, загружать и удалять может только владелец продукта.
4. **Отдельный пункт в меню** (сайдбар) со страницей, где можно:
   - просмотреть все вложения продукта;
   - загрузить новые;
   - скачать или открыть имеющиеся;
   - удалить вложение целиком (строка в БД и объект в хранилище).

Квоты и запрет исполняемых: до 10 МБ на файл, до 200 МБ на продукт.

Версионирование, теги, превью и правку `.md` в вебе не делать.

## Второй этап (вне этого требования)

Привязка уже загруженных вложений к сущностям проекта (гипотезы и далее). Junction-таблицы и UI прикрепления в редакторах — отдельная задача; схема вложений на первом этапе не должна знать про типы сущностей.

### Выполненные изменения:

1. **Таблица `attachments`**: `product_id`, отображаемое имя, исходное имя файла, SHA-256, размер, MIME, путь в Storage. Дедуп — `UNIQUE (product_id, content_hash)`. Лимит 10 МБ на файл (`CHECK`), 200 МБ на продукт (триггер). Исполняемые по расширению запрещены. RLS через владельца продукта.
2. **Storage**: приватный bucket `attachments`, путь `{product_id}/{attachment_id}`. Политики объекта через `SECURITY DEFINER` (`user_owns_attachment_object`) — прямой `EXISTS` в `products` из `storage.objects` на загрузке не проходил.
3. **Страница библиотеки** (`/attachments`, пункт в сайдбаре): список, квота, загрузка (в т.ч. несколько файлов), дедуп с тостом «This file already exists», скачивание, удаление с подтверждением (объект, затем строка).

Junction-таблиц и привязок к гипотезам/фичам/целям нет — это второй этап.
